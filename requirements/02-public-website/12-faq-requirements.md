12 – FAQ Page Requirements
1. Document Information
- Project: Aditi Caterers Website
- Document: Frequently Asked Questions (FAQ) Page Requirements
- File Name: 12-faq-requirements.md
- Page Route: /faq
- Languages: English and Marathi
- Status: Draft – answers involving business policies require owner confirmation
2. Purpose
The FAQ page provides visitors with clear answers to common questions about Aditi Caterers' services, catering options, packages, menus, booking process, event requirements, and enquiry process.

It should help visitors understand the service before contacting the catering team, while making it easy to submit an enquiry when an answer is unavailable.

The page must not display unconfirmed prices, booking policies, payment rules, cancellation terms, service-area claims, or promises as facts.
3. Goals
- Help visitors quickly find answers to common catering questions.
- Organize questions into meaningful categories.
- Support English and Marathi content.
- Provide a simple, accessible question-and-answer interface.
- Allow visitors to search FAQs, if the FAQ collection is large enough.
- Link visitors to relevant pages such as Packages, Food Menu, Contact, and Booking/Enquiry.
- Allow authorized administrators to manage FAQ content.
- Keep answers accurate, approved, and up to date.
4. Page Layout and UI
4.1 Page Header
Display:
- Page title: Frequently Asked Questions
- Short description explaining that visitors can find answers to common catering questions.
- Breadcrumb: Home > FAQ
Suggested copy:
Have questions about our catering services, packages, menu, or booking process? Browse the answers below or contact our team for assistance.

A Marathi version must be available through the website language selector.
4.2 FAQ Content Area
- Display FAQs grouped by category.
- Use accessible accordion components to expand and collapse answers.
- Keep the question visible when its answer is collapsed.
- Provide a clear visual indicator for expanded/collapsed state.
- Use spacing and typography consistent with the website's brand guidelines.
- Avoid overcrowding the page with too many open answers.
- Configure whether one or multiple FAQ items can be open at a time.
4.3 FAQ Accordion
Each FAQ item must include:
- Question
- Answer
- Category
- Display order
- Language-specific content
- Published/unpublished state
Behavior:
- Clicking or keyboard-activating a question opens its answer.
- Activating an open question closes it.
- Accordion state must be visually clear.
- Use semantic buttons and appropriate accessibility attributes.
- Avoid using non-semantic clickable divs for accordion triggers.
5. FAQ Categories
The page should support categories that can be configured by the admin.

Suggested default categories:
1. General Information
2. Catering Services
3. Packages & Pricing
4. With Material / Without Material
5. Food Menu & Customization
6. Booking & Enquiry
7. Event Date & Guest Count
8. Payment & Advance
9. Changes & Cancellation
10. Service & Event Preparation
Categories must be reviewed by the business owner. Remove categories that are not relevant to the actual service or policies.
5.1 Category Navigation
- Show category tabs, filter chips, or a category list when useful.
- On mobile, category navigation must remain easy to use without horizontal overflow.
- Selecting a category should filter the displayed FAQ items.
- Include an “All Questions” option.
- If a category has no published FAQs, do not show an empty category to visitors.
6. FAQ Search (Optional)
If there are many published FAQs, provide a search field.

Search requirements:
- Search questions and answer text.
- Support the current selected language.
- Ignore leading/trailing whitespace.
- Display a clear empty state when no results match.
- Provide a way to clear the search.
- Search should not require a page reload.
If the FAQ collection is small, category filtering may be sufficient and the search field may be omitted.
7. Suggested FAQ Content
These are suggested questions to guide content preparation. Answers must be written and approved by Aditi Caterers before publishing.
7.1 General Information
- What catering services does Aditi Caterers provide?
- Which types of events do you cater?
- How can I contact Aditi Caterers?
- In which locations do you provide catering services?
- Can I request a customized catering arrangement?
7.2 Catering Services
- Do you provide catering for weddings?
- Do you cater birthdays and engagement ceremonies?
- Can you provide catering for corporate or other events?
- Do you offer catering with material and without material?
- Can I discuss my event requirements before booking?
Only publish event types and services that the business has confirmed it offers.
7.3 Packages & Pricing
- Do you have catering packages for different budgets?
- How is package pricing calculated?
- Can I request a package for a specific number of guests?
- Can I customize a package?
- Are additional menu items charged separately?
- How can I get a quotation for my event?
Answers may refer visitors to the Packages page or the Contact/Enquiry form. Do not publish unapproved prices or claim that every package is available for every event.
7.4 With Material / Without Material
- What does “With Material” catering mean?
- What does “Without Material” catering mean?
- What items or services are included in each type?
- Can I choose the catering type according to my requirements?
- How are rates determined for each catering type?
The exact definitions, inclusions, exclusions, equipment, staffing, transport, and responsibilities must be approved by the business owner.
7.5 Food Menu & Customization
- Where can I view the food menu?
- Can I select dishes for my event?
- Can I request changes to a package menu?
- Are special menu requirements considered?
- Can I choose between Chapati and Puri, or between Rice and Pulao, if offered in a package?
- Are menu items subject to availability?
Only publish customization options, dietary accommodations, menu availability, and substitutions that the business can actually support.
7.6 Booking & Enquiry
- How can I enquire about catering for my event?
- How far in advance should I contact you?
- What information should I provide when making an enquiry?
- How will I know if my event date is available?
- When is a booking considered confirmed?
Do not publish an exact advance-booking window or booking-confirmation policy until approved.
7.7 Event Date & Guest Count
- Can I enquire if my event date is not finalized?
- Can I request catering for a small or large gathering?
- Can I change the guest count after submitting an enquiry?
- How should I share the estimated number of guests?
The business owner must confirm guest-count limits, adjustment deadlines, and whether large events require a separate quotation.
7.8 Payment & Advance
Potential questions:
- Is an advance payment required to confirm a booking?
- What payment methods do you accept?
- When is the remaining amount payable?
- Will I receive a payment confirmation or receipt?
Payment terms, accepted payment methods, receipt practices, and due dates must be confirmed by the business owner before publication. Do not invent payment terms.
7.9 Changes & Cancellation
Potential questions:
- Can I change the menu after booking?
- Can I increase or decrease the guest count?
- What happens if an event date changes?
- What is the cancellation policy?
- Are any charges applicable for changes or cancellations?
These answers must reflect the actual approved policy. Do not publish a refund percentage, deadline, cancellation charge, or guarantee without owner approval.
7.10 Service & Event Preparation
Potential questions:
- What details should I provide about the venue?
- Do you need access to the venue before the event?
- What arrangements are needed for serving food?
- Can I discuss event-specific requirements with the team?
Do not claim venue inspections, equipment, staffing, setup, cleanup, or other services unless confirmed.
8. FAQ Content Requirements
Every FAQ must include:
- Question in English
- Answer in English
- Question in Marathi
- Answer in Marathi
- Category
- Unique identifier
- Display order
- Published/unpublished status
- Created and updated timestamps
Content rules:
- Answers must be clear, concise, and helpful.
- Avoid unnecessary technical or business jargon.
- Avoid exaggerated promotional claims.
- Use consistent terminology for catering types, packages, and booking stages.
- Keep English and Marathi answers equivalent in meaning.
- Avoid contradictory answers across FAQs and other website pages.
- Add links to related website pages where useful.
- Review content whenever service or policy details change.
9. FAQ Page Call-to-Action (CTA)
If visitors cannot find an answer, provide a clear CTA.

Suggested CTA:
Still have questions? Contact our team and tell us about your event.

CTA actions:
- Contact Us → /contact
- Enquire Now → approved booking/enquiry route
- WhatsApp Us → confirmed business WhatsApp number
CTA must be available in English and Marathi. Phone/WhatsApp contact details must be verified before production publishing.
10. Admin Panel – FAQ Management
Authorized administrators should be able to manage FAQ content.
10.1 FAQ List
Display:
- Question (selected language or primary language)
- Category
- Published status
- Display order
- Last updated
- Actions
Admin actions:
- Add FAQ
- View FAQ
- Edit FAQ
- Publish / Unpublish
- Delete (with confirmation)
- Reorder FAQs
- Filter by category and status
- Search questions
10.2 Add / Edit FAQ Form
Fields:
- Question – English
- Answer – English
- Question – Marathi
- Answer – Marathi
- Category
- Display order
- Published status
- Optional related page/link
Validation:
- Required question and answer for both languages, unless the owner approves a single-language publishing workflow.
- Category must be valid.
- Display order must be a valid number.
- Related link must be a safe, valid route or URL.
- Prevent accidental duplicate questions where practical.
- Show validation messages clearly.
10.3 Publishing Workflow
- Draft FAQs must not appear on the public page.
- Published FAQs must be visible in the appropriate language.
- Unpublishing must remove the FAQ from public results without deleting its record.
- Changes should take effect after a successful save.
- Deletion must require confirmation.
- Admin actions must require authentication and appropriate authorization.
11. Backend API Requirements
Use the existing project backend conventions (Node.js, Express, MongoDB, and Mongoose).
11.1 Public APIs
- GET /api/faqs – fetch published FAQs.
- GET /api/faqs/categories – fetch categories that contain published FAQs, if categories are served separately.
Query parameters for GET /api/faqs may include:
- language – en or mr
- category – category ID or slug
- search – optional text search
- page – optional page number
- limit – optional page size
For a small FAQ collection, the API may return the full published FAQ list without pagination. Choose the implementation based on actual content size and project conventions.
11.2 Admin APIs (Authentication Required)
- GET /api/admin/faqs – list FAQs, including unpublished items.
- GET /api/admin/faqs/:id – fetch one FAQ.
- POST /api/admin/faqs – create FAQ.
- PUT /api/admin/faqs/:id – update FAQ.
- PATCH /api/admin/faqs/:id/status – publish/unpublish FAQ.
- PATCH /api/admin/faqs/:id/order – update display order, if ordering is handled separately.
- DELETE /api/admin/faqs/:id – delete FAQ.
API requirements:
- Validate request data on the server.
- Return consistent response structures.
- Use appropriate HTTP status codes.
- Apply authentication and authorization to all admin endpoints.
- Support category filtering and pagination in admin list endpoint.
- Public endpoints must return only published FAQs.
- Do not expose internal admin fields publicly.
- Sanitize or safely render FAQ answer content to prevent cross-site scripting (XSS).
- Log errors without exposing stack traces or secrets.
11.3 Suggested API Response
Example public response:
{
  "success": true,
  "data": [
    {
      "id": "faq-id",
      "category": "booking",
      "question": "How can I enquire about catering?",
      "answer": "Submit an enquiry using our contact form.",
      "language": "en",
      "displayOrder": 1
    }
  ]
}
The actual response shape may be adjusted to support bilingual fields and follow the project's established API conventions.
12. MongoDB / Mongoose Schema
Suggested model: FAQ.
12.1 Suggested Fields
Field	Type	Required	Description
question.en	String	Yes	English question
answer.en	String	Yes	English answer
question.mr	String	Yes	Marathi question
answer.mr	String	Yes	Marathi answer
category	String / ObjectId	Yes	Category or category reference
slug	String	No	Optional URL-friendly identifier
displayOrder	Number	Yes	Display position
isPublished	Boolean	Yes	Public visibility
relatedLink	String	No	Related page route/link
createdBy	ObjectId	No	Admin who created the FAQ
updatedBy	ObjectId	No	Admin who last updated the FAQ
createdAt	Date	Yes	Creation timestamp
updatedAt	Date	Yes	Update timestamp


12.2 Schema Notes
- Use Mongoose timestamps where appropriate.
- Validate bilingual content.
- Use enum or category references for valid categories.
- Add indexes for published status, category, and display order as appropriate.
- Consider text indexes only if FAQ search requirements justify them.
- Avoid duplicate questions within the same category and language when practical.
- Keep admin-only fields excluded from public API responses.
13. FAQ Categories Management (Optional)
If the project requires dynamic category management, provide an admin-managed FAQ category collection.

Category fields may include:
- Name (English)
- Name (Marathi)
- Slug
- Display order
- Active status
- Created/updated timestamps
Admin capabilities:
- Add category
- Edit category
- Reorder category
- Activate/deactivate category
- Delete category only when it is not in use, or handle existing FAQs safely
If category management adds unnecessary complexity, use a predefined category list maintained in the backend configuration instead.
14. Security Requirements
- Admin FAQ management endpoints must be protected by authentication and authorization.
- Validate all incoming fields on the backend.
- Prevent stored XSS in FAQ answers and related links.
- If rich text is supported, sanitize allowed HTML elements and attributes.
- Do not allow unsafe JavaScript URLs in related links.
- Do not expose unpublished FAQs publicly.
- Avoid exposing internal admin metadata in public API responses.
- Protect database credentials and secret keys.
- Use HTTPS in production.
15. Accessibility Requirements
- Use semantic headings and section structure.
- Accordion triggers must be keyboard operable.
- Use buttons for accordion controls.
- Communicate expanded/collapsed state to assistive technologies.
- Maintain visible focus styles.
- Ensure readable color contrast.
- Do not rely on color alone to convey category or state.
- Provide meaningful labels for FAQ search and category controls.
- Ensure language changes are understandable and consistent.
16. Responsive Design Requirements
Desktop
- Use a readable content width.
- Categories may be displayed as a sidebar or horizontal navigation.
- FAQ accordion should not span an excessively wide text area.
- CTA section should be clearly visible near the end of the page.
Tablet
- Categories and FAQ content should adapt to available space.
- Keep accordion buttons and text comfortable to read and tap.
Mobile
- Stack sections vertically.
- Use full-width accordion rows.
- Ensure category navigation does not create horizontal page overflow.
- Make touch targets comfortable.
- Keep CTA buttons easy to tap.
- Prevent horizontal scrolling.
17. SEO Requirements
- Page title: Frequently Asked Questions | Aditi Caterers
- Meta description: a concise summary of the catering FAQ page.
- Use one clear H1.
- Organize category headings logically.
- FAQ questions should be meaningful and descriptive.
- Use crawlable HTML content rather than relying exclusively on client-side inaccessible rendering.
- Add structured data only when valid and supported by the actual visible content and current search-engine guidelines. Do not assume FAQ rich results will appear in search.
- Avoid duplicate or misleading FAQ content.
18. Performance Requirements
- Keep FAQ page lightweight.
- Avoid unnecessary animations.
- Lazy-load unrelated page images, if any.
- Avoid excessive API requests when categories or FAQs can be retrieved efficiently.
- Cache public published FAQ data appropriately, while ensuring updated content can be refreshed.
- Search/filter interactions should be responsive.
- Keep third-party scripts to a minimum.
19. Testing Requirements
UI Tests
- FAQ page loads successfully.
- Page header and breadcrumb are displayed.
- Categories display correctly.
- Accordion opens and closes correctly.
- All Questions and Answers display in the selected language.
- CTA links route to the correct pages.
- Responsive layout works on desktop, tablet, and mobile.
- Empty-state display works when no FAQs are published.
Search and Filter Tests (If Implemented)
- Search matches question and answer content.
- Search handles whitespace and case appropriately.
- Category filter returns correct items.
- Search and category filters work together.
- Clear-search action resets the results.
- No-results message is shown when appropriate.
Admin Tests
- Admin can add, edit, publish, unpublish, reorder, and delete FAQs.
- Validation errors are shown for incomplete or invalid fields.
- Draft FAQs are not visible publicly.
- Published FAQs are returned by public API.
- Admin category filters and search work.
- Unauthenticated users cannot access admin FAQ endpoints.
- Unauthorized roles cannot modify FAQ records.
API and Database Tests
- Public API returns published FAQ content only.
- Language selection returns the correct localized content.
- Category filter works.
- Invalid query parameters are handled safely.
- FAQ records persist correctly in MongoDB.
- Create/update/delete operations behave as expected.
- Backend validation and sanitization work.
- API error responses are consistent.
